# Hello! Mix — 使い方と編集ガイド

`index.html` だけで動く、ハロー！プロジェクトの個人用・非公式プレイリスト作成ツールです。HTML・CSS・JavaScriptをすべて内包しています。サーバー処理、データベース、外部API、外部ライブラリ、ビルド作業は不要です。この説明書は公開時に置かなくても動きます。

## 今回の仕様

- 初期データは13グループ・70曲のセレクションです。全楽曲や最新リリースの網羅・自動更新は行いません。
- 編集・保存するプレイリストは1件。名前も変更できます。
- ライブラリの曲名または「＋」で追加。同じ曲IDは重複追加できません。
- グループで絞り込み、曲名で部分一致検索できます。英字の大小、全角・半角、ひらがな・カタカナ、空白の違いを吸収します。漢字の読み仮名検索には対応しません。
- 「↑」「↓」で1曲ずつ移動、「×」で削除。「元に戻す」で直前の曲編集を1回取り消せます。元に戻す履歴は再読み込みで消え、名前の編集は対象外です。
- 「リセット」は確認後、全曲を削除します。プレイリスト名は残ります。
- 曲数・グループ構成のカラーバーを表示します。
- PCでは楽曲とプレイリストを左右に配置。幅760px以下では縦並びになり、下のナビゲーションで移動できます。

### おまかせミックス

1. 参加グループを選択します。初期状態では主要7グループが選択済みです。過去グループも個別に選べます。
2. 1〜200の整数で曲数を指定します。
3. 必要なら「このグループを多めに」で1グループを選びます。
4. 「ランダムで生成する」で現在のリストを置き換えます。すでに曲がある場合は確認を表示します。
5. 生成後も通常どおり追加・削除・並び替えできます。

抽選は対象曲全体からの重複なし抽選です。「多め」はそのグループの各曲に3倍の重みを付けます。曲数や割合の確約ではありません。指定しない場合は各曲が同じ重みなので、収録曲が多いグループほど選ばれやすくなります。複数グループの選択は混合候補の指定であり、すべてのグループが必ず入るわけではありません。

指定曲数が対象曲数を上回った場合は、対象の全曲をランダムな順番で入れ、実際の曲数を通知します。0グループでは生成できません。ライブラリの検索・絞り込みは、ランダム生成の条件とは独立しています。

### Apple Music

各曲の「♫」から、`曲名 + アーティスト名` を検索するページを新しいタブで開きます。

```text
https://music.apple.com/jp/search?term=（URLエンコードした検索語）
```

認証やAPIは使いません。検索結果・配信状況はApple Music側に依存します。このアプリ内での音楽再生、Apple Musicへのプレイリスト転送は行いません。

## 楽曲を追加する場所

`index.html` をテキストエディターで開き、`const SONGS = [` を検索してください。配列内に次のような1行を追加します。

```js
{ id:'jj-009', group:'juice', title:'追加する曲名' },
```

| 項目 | 意味 |
| --- | --- |
| `id` | 全曲で一意の文字列。保存データとの照合に使うため、公開後は変更・使い回しをしないでください。 |
| `group` | 下記のグループID。絞り込み、抽選、色に使います。 |
| `title` | 表示と検索に使う曲名。 |
| `artist` | 任意。Apple Music検索に使うアーティスト表記を上書きします。省略時はグループ名です。 |

名義が年で変わる曲は、例えば次のようにできます。

```js
{ id:'mm-009', group:'mm', title:'追加する曲名', artist:"モーニング娘。'24" },
```

文字列に半角の `'` が含まれる場合は二重引用符で囲むか、`\'` と記述してください。各行末のカンマを忘れないようにします。追加後、ページを再読み込みすると自動で一覧・曲数・抽選候補に反映されます。

| group | グループ |
| --- | --- |
| `mm` | モーニング娘。 |
| `angerme` | アンジュルム |
| `juice` | Juice=Juice |
| `tsubaki` | つばきファクトリー |
| `beyooooonds` | BEYOOOOONDS |
| `ocha` | OCHA NORMA |
| `rosy` | ロージークロニクル |
| `berryz` | Berryz工房 |
| `cute` | ℃-ute |
| `buono` | Buono! |
| `smileage` | スマイレージ |
| `country` | カントリー・ガールズ |
| `kobushi` | こぶしファクトリー |

スマイレージは旧名義として独立したグループにしています。モーニング娘。の年別名義は同じグループにまとめています。

### 新しいグループや色を追加・変更する

`const GROUPS = [` が設定箇所です。例：

```js
{ id:'newunit', name:'追加するユニット', short:'NU', color:'#a8d7e8' },
```

その後、`SONGS` に `group:'newunit'` の曲を追加します。検索用・生成用のグループボタンは自動で増えます。初期選択の7グループは、`state` 内の `GROUPS.slice(0,7)` で指定しています。

## コードの構成

番号付きのコメントで区切っています。

1. デザイントークン・CSS：色、レイアウト、レスポンシブ指定。
2. 楽曲データ：`GROUPS` と `SONGS`。
3. データ操作：検索正規化、保存形式の検証、URL生成、重み付き抽選。
4. 状態と保存：`state`、`restore()`、`persist()`、`commit()`。
5. 描画：ライブラリ・プレイリスト・条件ボタンの描画。
6. 操作：追加、削除、移動、生成、初期化。

可変文字列は `textContent` で画面に挿入しています。曲名をHTMLとして解釈させない構成です。

## LocalStorageの仕組み

曲を編集したときと名前を入力したときに、次のキーへJSON形式で保存します。

```js
// キー
'hello-mix.playlist.v1'

// 保存内容の例
{
  "version": 1,
  "name": "今日のハロプロミックス",
  "songIds": ["jj-001", "mm-001", "be-006"]
}
```

`songIds` の並びが曲順です。起動時に読み込み、現在の `SONGS` と照合して復元します。データから削除された曲IDは復元時に除外されます。曲名だけ修正して同じIDを残せば、保存済みプレイリストにも新しい曲名が表示されます。

- 保存はその端末・そのブラウザ・同じオリジン内に限られます。PCとiPhone、SafariとChromeは自動同期しません。
- 履歴・サイトデータの削除、プライベートブラウズの終了などで保存が失われる場合があります。
- 複数タブで同時編集すると最後の保存が優先されます。リアルタイム同期は実装していません。
- 同じオリジン上の別のコピーも同じキーを使います。独立させたい場合は `STORAGE_KEY` をコピーごとに変更してください。
- 保存不可の場合は右上に警告を表示し、その画面での編集は続けられます。
- 壊れた保存データや未対応バージョンは勝手に上書きせず、次回編集時に上書きするか確認します。
- `file://` で直接開いたときの保存動作はブラウザによって異なるため、継続利用はGitHub PagesのHTTPS URLを使ってください。直接開いたファイルの保存内容は公開先に移りません。

## GitHub Pagesへの配置

1. GitHubでリポジトリを作成します。GitHub Freeで使う場合は公開リポジトリを選ぶのが簡単です。
2. リポジトリの **Add file → Upload files** から `index.html` をアップロードしてコミットします。`outputs` フォルダごとではなく、**リポジトリの一番上に `index.html`** がある状態にします。
3. **Settings → Pages → Build and deployment** を開きます。
4. **Source** を **Deploy from a branch** にします。
5. **Branch** に `main`、フォルダに **/(root)** を選び、**Save** します。
6. 公開処理が終わるとPages設定にURLが表示されます。PCとiPhoneでそのURLを開いて使います。

通常のプロジェクト用リポジトリのURLは `https://ユーザー名.github.io/リポジトリ名/` です。更新するときは同じ場所の `index.html` を置き換えてコミットします。反映後にページを再読み込みしてください。同じオリジンと保存キーを保てば保存内容を再利用できます。

HTMLには相対アセットもビルド処理もないため、GitHub Actionsの設定ファイルやパッケージのインストールは不要です。公開されたHTMLと楽曲一覧は閲覧者に見えますが、作成した個人のプレイリストはブラウザ内だけに保存されます。

手順の参照：[GitHub公式：公開元の設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

リポジトリ: https://github.com/hare0413-blip/hello-mix 。公開URLはリポジトリの Settings → Pages で確認できます。
